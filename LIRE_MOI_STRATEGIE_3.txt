✅ STRATÉGIE 3 : POURQUOI CETTE APPROCHE ?

🎯 PRINCIPE :
   • Chaque développeur fait des modules COMPLETS (backend + frontend)
   • 4 modules chacun
   • Dépendances minimales (1 seul blocage de 3 jours)

📊 RÉPARTITION :

   DÉVELOPPEUR 1 : Académique + Opérations Simples (23 jours)
   ├── S1 : Auth & Users (5j) - Fondation du système
   ├── S2 : Salle (6j) - CRUD complet
   ├── S3 : Filière (6j) - Cycles et années
   ├── S4 : Réclamation (6j) - Workflow simple
   └── S5-6 : Aide Dev2 (12j) - Support sur Emploi et Réservation

   DÉVELOPPEUR 2 : Gestion Avancée (29 jours)
   ├── S1 : Administration (5j) - Approbation inscriptions
   ├── S2-3 : Matière (8j) - Attend Filière (3j) ⚠️
   ├── S4-5 : Emploi du Temps (10j) - Module le plus complexe
   └── S6 : Réservation (6j) - Algorithmes de priorité

✅ AVANTAGES :
   • Équilibre parfait : 4 modules chacun
   • Charge similaire : 23j vs 29j (différence de 6 jours)
   • Dépendances minimales : 1 seul blocage (3 jours en S3)
   • Modules complets : Backend + Frontend
   • Pas de conflit Git : Modules différents = fichiers différents
   • Collaboration renforcée : Dev1 aide Dev2 en S5-S6
   • Apprentissage complet : Chaque dev maîtrise toute la stack

⚠️ POINT CRITIQUE :
   • Dev2 doit attendre que Dev1 termine Filière (fin S3)
   • Pendant ce temps, Dev2 travaille sur Administration
   • C'est le SEUL point de blocage du projet !
